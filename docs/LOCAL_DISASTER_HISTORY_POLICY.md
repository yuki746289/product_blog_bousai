# 地域災害史・地域防災記事 作成方針

## 1. 目的

地域名を冠した防災記事を、単なる地域名差し替えページや災害年表ではなく、**その土地で過去に何が起き、なぜ被害が生じ、現在どの災害にどう備えるかを読者が理解できる記事**として作成する。

地域記事はSEO目的の大量生成を行わず、独立した地域価値・一次情報・現在の行動価値がある場合のみ作成する。

特に地域記事では、事実や数値を並べるだけでなく、**公的データから読み取れる地域課題を明示し、その課題に対応した具体的な備えへ接続する**。

文字数は品質確認の目安として扱うが、地域記事の主目的は文字数達成ではない。**事例、具体例、被害の経過、地域固有の条件、生活への影響、現在の対策を掘り下げた結果として、十分な本文量になること**を基本とする。

## 2. 基本構造

地域災害史記事は、原則として次の役割を持つ。

1. **地域の特徴**
   - 地形、河川、海岸、山地、低地、都市構造等、災害と関係する地域条件を整理する。
   - 一般論を地域名だけ差し替えない。

2. **主な過去災害**
   - 年月日、災害種別、被害地域、確認できる被害概要を時系列で整理する。
   - 年表を並べるだけでなく、その災害が地域に何を示したかを説明する。

3. **被害データから読み取れる地域課題**
   - 死者・負傷者、浸水戸数、浸水深、浸水継続時間、雨量、津波高、火災件数、停電・断水、降灰量等、記事テーマに関係するデータを一次資料から確認する。
   - 数値そのものを強調するのではなく、「どの被害が大きかったか」「どの条件が生活上の弱点になったか」を説明する。
   - 1件の過去災害だけから一般化せず、地形・現在の想定・複数資料と照合する。

4. **現在のハザード情報**
   - 現在の自治体ハザードマップ、国・都道府県等の公的情報へ接続する。
   - 歴史的被害範囲と現在の想定区域を同一視しない。

5. **データから対策へ落とし込む**
   - 原則として、主要な地域課題ごとに `データ / 読み取り / 対策` の3段階で整理する。
   - 例:
     - データ: 長期間の浸水実績・現在の浸水継続時間想定
     - 読み取り: 水が引くまで自宅孤立や車移動困難が続く可能性
     - 対策: 水・食料・携帯トイレの備蓄日数、車の事前移動、垂直避難・早期避難の確認
   - 対策はデータから合理的に導ける範囲に限定し、独自の安全基準・避難開始時刻・必要備蓄量を断定しない。
   - 公的機関に具体的な推奨量・行動基準がある場合は、その一次資料を優先する。

6. **現在の備え・行動**
   - 既存の防災くらしガイド記事へ内部リンクし、地域史を実際の備えへつなげる。
   - 例: 洪水、土砂災害、高潮、津波、台風前準備、停電、断水、車の冠水、家具転倒、火災、火山灰等。

7. **具体的な事例・詳細**
   - 県・市全体の集計値だけで終わらせず、一次資料で確認できる場合は、**被害が集中した地区、河川、沿岸部、住宅地、道路、施設、避難上の問題などの具体例**を入れる。
   - 「何人・何棟」だけでなく、**なぜ被害が広がったか、どのような順序で生活へ影響したか**を説明する。
   - 停電、断水、道路寸断、交通停止、長期浸水、避難生活、車両被害、物流、トイレ、学校・職場等、生活への影響が公的資料で確認できる場合は積極的に扱う。
   - 複数の災害を扱う場合は、単に年代順に並べるのではなく、**災害ごとに被害の特徴や弱点がどう違ったか**を比較する。
   - 具体例が確認できない場合に、一般論や推測で穴埋めしない。

## 3. 「データ → 読み取り → 対策」のルール

### 3.1 使ってよいデータ

可能な限り公的・一次資料にある次のような値を使用する。

- 人的被害・建物被害
- 浸水戸数、浸水深、浸水継続時間
- 降水量、風速、潮位・高潮偏差
- 震度、津波高、津波到達・浸水想定
- 火災件数、焼損棟数
- 停電・断水・交通途絶等のライフライン被害
- 火山灰の厚さ・降灰量・噴火回数
- 現在の想定浸水区域、基準水位、指定避難施設数等

### 3.2 読み取りでしてはいけないこと

- 過去データから次回発生日や周期を推定する
- 被害が少なかった地域を「安全」と判定する
- 1回の被害データだけから地域全体の危険度を順位付けする
- ハザードマップの想定を「必ずその深さになる」と断定する
- 数値の大小だけで避難要否を独自判定する

### 3.3 対策の書き方

対策は、読者が自宅で確認できる行動まで具体化する。

例:

| データ・事実 | 読み取れる課題 | 記事内で示す対策 |
|---|---|---|
| 浸水が長期間続いた | 物流・車・在宅生活が長く制限される | 備蓄、車の事前移動、避難経路確認 |
| 建物倒壊が多かった | 室内負傷・閉じ込めリスク | 耐震確認、家具固定、寝室配置 |
| 火災被害が集中した | 地震後の出火・通電火災 | 感震ブレーカー、避難時の電源確認 |
| 津波浸水域が広い | 水平避難だけでは距離が足りない地域がある | 高台・津波避難ビル・タワーを事前確認 |
| 多量の降灰が想定される | 視界・交通・ライフラインへの影響 | 降灰予報確認、不要不急の運転回避、防灰用品 |

### 3.4 内容の厚みを判断する基準

地域記事は総文字数だけでPASSにしない。主要災害・主要論点について、一次資料が許す範囲で次を確認する。

- 地域全体の集計値以外に、地域固有の具体例・事例がある
- 被害が発生・拡大した条件や経過が説明されている
- 生活への具体的な影響が説明されている
- 過去事例と現在のハザード・制度・対策の違いが分かる
- 複数事例がある場合、それぞれの特徴の違いを説明している
- 読者が自宅・勤務先・学校・移動経路等へ置き換えて考えられる
- 関連する行動記事・商品記事がある場合、自然な位置から接続している

**見出しが多くても各章が短い要約だけなら「内容が十分」と判定しない。** 反対に、同じ意味の説明を言い換えて文字数だけ増やすこともしない。

## 4. 情報源の優先順位

地域災害史では、可能な限り次の一次・公的情報を優先する。

- 国・都道府県・市区町村の災害記録、地域防災計画、ハザードマップ
- 気象庁の災害・気象資料、地震・津波・火山資料
- 国土交通省、地方整備局、河川事務所等の水害・河川資料
- 国土地理院の地形・地図・災害関連資料
- 消防庁、内閣府等の災害記録
- 公的博物館、文書館、図書館、自治体史等の歴史資料

報道・民間資料を使用する場合も、死者数、雨量、震度、浸水範囲等の重要数値は可能な限り一次情報へ戻って確認する。

## 5. 歴史情報の扱い

### 5.1 現在情報と分離する

歴史情報は過去の事実として扱い、現在の避難判断・現在の施設状況と混ぜない。

例:

- 過去に避難所として使われた施設 → 現在も指定避難所とは限らない
- 過去の浸水区域 → 現在の洪水浸水想定区域と一致するとは限らない
- 過去の自治体境界・地名 → 現在と異なる場合がある

### 5.2 数値を盛らない

被害人数、浸水戸数、雨量、最大風速、震度、津波高等について資料間で差がある場合、無理に一つへ統一しない。

- 集計時点
- 対象範囲
- 単位
- 出典

が異なる可能性を確認し、必要なら「資料により集計が異なる」と明記する。

### 5.3 歴史から未来を断定しない

禁止例:

- 「30年周期だから次は○年に来る」
- 「過去に浸水していないから安全」
- 「この地区は昔被害が少なかったので避難不要」

過去の記録は地域理解の材料であり、現在の避難判断は最新の警報・避難情報・ハザード情報を優先する。

## 6. 鮮度管理

既存の `FRESHNESS_POLICY.md` を適用しつつ、地域記事では情報を2種類に分ける。

### A. 歴史的記録

- 過去の災害年月日・被害記録そのものは低頻度更新でよい。
- 新しい公的資料、訂正、詳細調査が公開された場合に再確認する。

### B. 現在情報

次は鮮度が高いため、公開時・更新時に現行一次情報を確認する。

- ハザードマップ
- 指定緊急避難場所・指定避難所
- 自治体の防災ページ
- 河川・砂防・高潮・津波・火山等の現在の想定区域
- 防災アプリ、連絡先、施設利用条件

施設の「現在開放中」「無料」「利用可能」「空きあり」等のリアルタイム情報は、通常の地域災害史記事へ恒久情報として固定しない。

## 7. 記事化の判定

地域記事を新規作成する前に、最低限次を確認する。

- その地域に独立して説明する災害史・地域特性がある
- 公的・一次資料を複数確保できる
- 既存の全国向け記事を地域名へ置換するだけにならない
- 読者が現在の備え・行動へつなげられる
- `データ → 読み取り → 対策` を少なくとも2論点以上で成立させられる
- 地域全体の集計値以外に、具体的な地区・条件・生活影響等の地域固有情報を複数示せる
- 市区町村、都道府県、広域地域のどの粒度が適切か説明できる
- 近隣地域記事との重複・薄いページ量産にならない

条件を満たさない場合は、新規記事ではなく既存記事内の地域事例・Q&A・補足欄として扱う。

## 8. 地域粒度

原則として検索需要だけで行政区分を決めない。

- **都道府県単位**: 複数災害を俯瞰する場合
- **市区町村単位**: 河川、低地、沿岸、山地等の地域特性が明確な場合
- **流域・湾岸等**: 行政境界より災害メカニズムのまとまりが重要な場合

同一内容を都道府県版・市版・町版で複製しない。

## 9. 推奨記事構成例

1. この地域では何に備えるべきか
2. 地形・河川・沿岸等の地域特性
3. 主な災害の歴史（年表）
4. 被害データで見る地域の弱点
5. 災害Aの具体的事例・被害経過・教訓
6. 災害Bの具体的事例・被害経過・教訓
7. 生活への影響（停電・断水・交通・避難等）
8. データから考える具体的な備え
9. 現在のハザードマップで確認すること
10. 自宅・移動・車・避難の備え
11. 防災くらしガイド内の関連実用・商品記事
12. 公的資料・参考資料

章名は記事ごとに変え、固定テンプレートの機械的反復を避ける。

## 10. 画像・地図

- 被災写真は公的資料・利用条件が明確な資料を優先する。
- 古写真を現在の街並みとして扱わない。
- 地図・ハザードマップの転載条件を確認し、転載できない場合は公式ページへのリンクを使用する。
- AI生成画像で実在する災害現場・過去の被害状況を再現し、史実写真のように見せない。

## 11. 内部リンク

地域史記事は単独で完結させず、地域で問題となる災害種別に応じて既存実用記事へ接続する。

例:

- 河川氾濫 → 洪水キキクル・避難判断
- 内水氾濫 → 冠水・車・地下空間
- 土砂災害 → 土砂キキクル・避難
- 高潮 → 高潮避難
- 津波 → 津波避難
- 地震倒壊 → 家具固定・在宅避難
- 地震火災 → 感震ブレーカー
- 長期停電 → 停電・冷蔵庫・暑さ寒さ
- 火山灰 → 停電・車・備蓄等、実際に関連する既存記事

内部リンクは「地域記事 → 一般論」だけでなく、一般記事から代表的地域事例へ戻す必要性も個別に判断する。

グッズとの関連が自然な場合は、**地域記事 → 行動・選び方記事 → 商品記事 → Amazon** の順を基本とし、安全情報より商品導線を前に出さない。

## 12. 禁止事項

- 地域名だけを差し替えた大量ページ生成
- 被害の大きさを煽るタイトル・表現
- 出典不明の災害伝承を事実として断定
- 死者・被災者数等のセンセーショナルな強調
- 数値を並べるだけで地域の備えへ結び付けない記事
- 集計値だけで終わり、具体的な被害事例・生活影響を調べない記事
- 過去の被害を根拠に現在の安全・危険を断定
- 現在の避難所・施設情報を古い資料だけで掲載
- 災害史と関係の薄い観光・地域紹介による水増し
- 同じ意味の一般論を言い換えて文字数だけ増やす


## 12.5 災害事例の同一性・鮮度・分類

地域災害史で扱う実在事例の**同一イベント判定、直近/過去の件数、候補母集団、調査終了条件、採否記録、線状降水帯/局地的大雨の分類**は、`DISASTER_CASE_RESEARCH_POLICY.md` を正本とする。

地域災害史として追加する条件:

- 事例を地域の地形・生活影響・防災行動へ接続する。
- 広域災害を扱う場合、その地域で実際に発生・観測・被害があった根拠を持つ。
- 表の行数ではなく独立イベント数で数える。
- 地域史上重要な古い事例は「過去の代表事例」として残し、「直近」の新しさを損なわない。

## 14. 直近事例表と過去事例表

複数事例を扱う地域災害史・発生履歴記事では、`DISASTER_CASE_RESEARCH_POLICY.md` に従い、原則として次を分離する。

### A. 直近の大雨・災害事例
- 件数・並び順・不足時の扱いは災害事例ポリシーを正本とする。
- 日時、現象、実測雨量、公式発表、被害・生活影響を可能な範囲で示す。
- 地域記事では「その地域で何が起きたか」が分かる根拠を優先する。

### B. 過去の代表的な大雨・災害事例
- 件数・選定方法は災害事例ポリシーを正本とする。
- 地域特性、被害メカニズム、現在の備えを理解する価値が高い事例を選ぶ。
- 現行制度以前の事例へ現在の警戒レベル等を後付けしない。

### 線状降水帯県別記事
- 線状降水帯の実発生が一次資料で確認できる都道府県だけを県別シリーズの対象とする。
- 県別titleの基本形は **「○○県の線状降水帯｜過去の発生履歴・直近事例を一覧で解説」** とする。
- 実発生を確認できない都道府県は件数合わせで線状降水帯県別ページを作らない。必要なら一般の豪雨・都市型水害記事へ役割変更する。
- 線状降水帯ではない局地的大雨・短時間強雨は、関連豪雨として明確に区別し、線状降水帯発生件数へ含めない。
- 全国年表・地域別記事でも、直近事例と歴史的代表事例の役割を混同しない。
