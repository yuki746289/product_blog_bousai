# Amazon商品リンク 品切れ・販売終了対応ポリシー

更新日: 2026-09-07
対象: 防災くらしガイドの商品紹介・商品導線

## 1. 目的

Amazonの商品リンクについて、品切れ、販売終了、商品ページ消失、後継商品への切替が発生した場合に、記事本文・商品画像・価格・説明とリンク先が不整合になることを防ぐ。

本ポリシーはCreators API等が利用できない期間の手動運用と、将来API連携した場合の自動監視の両方に適用する。

## 2. 基本原則

1. **Amazon商品ページを無断スクレイピングして在庫監視しない。**
   - HTML構造変更、Bot対策、利用条件の問題があり、安定運用に向かない。
2. APIが利用可能な場合は、許可された公式APIを優先する。
3. APIが利用できない間は、記事公開時・更新時・定期レビュー時に手動確認する。
4. 品切れだからといって、本文を確認せずASINだけを別商品へ差し替えない。
5. 後継商品へ変更する場合は、容量・出力・サイズ・用途等、記事中の説明を再検証する。
6. 価格は固定値として扱わず、確認日を明記する。現在価格はAmazon等のリンク先を優先する。
7. 販売終了商品を「おすすめ」として放置しない。
8. アフィリエイト収益より、記事内容との適合性と読者の安全・有用性を優先する。

## 3. 商品ステータス

商品単位で次の状態を使用する。

| status | 意味 | 公開ページの扱い |
|---|---|---|
| ACTIVE | 商品ページ・販売継続を確認 | 掲載可 |
| TEMPORARILY_UNAVAILABLE | 一時的な在庫切れの可能性 | 短期間は掲載可。長期化なら再評価 |
| REVIEW_REQUIRED | 状態不明、仕様変更、リンク異常 | 更新完了まで要確認 |
| DISCONTINUED | 販売終了・旧製品化を確認 | 原則、現行おすすめから外す |
| REPLACED | 後継商品へ置換済み | 新商品のレビュー記録を残す |
| REMOVED | 商品導線を削除 | 本文が商品依存なら同時修正 |

## 4. 確認タイミング

### 必須

- 新規商品記事の公開前
- 商品名、価格、画像、ASINを変更する前
- 商品記事の定期レビュー時
- ユーザーからリンク切れ・品切れ報告があった時

### 定期確認

APIなし期間は、原則として商品記事を**30〜60日単位**で確認候補にする。
ただし、アクセスがほとんどない期間はGitHub Actionsを消費して自動巡回せず、記事更新時または手動レビュー時にまとめて確認してよい。

季節需要が強い記事は、台風・豪雨・停電等の需要期前に優先確認する。

## 5. 手動確認項目

商品ごとに最低限、次を確認する。

- Amazonリンクが対象商品へ到達するか
- 商品名・型番が本文と一致するか
- ASINが意図した商品か
- メーカー公式ページで現行商品として確認できるか
- 容量、出力、重量、数量等の主要仕様が本文と一致するか
- 商品画像の利用元が有効か
- 記載価格の確認日が古すぎないか
- 後継商品が出ていないか

Amazon側の一時的な在庫表示だけで販売終了と断定しない。メーカー公式情報も確認する。

## 6. 販売終了・後継商品発見時

### 置換する場合

1. 元の商品が担っていた記事内の役割を確認する。
2. 同じ用途・容量帯・価格帯等から候補を探す。
3. メーカー公式情報で主要仕様を確認する。
4. 商品説明、比較表、価格、画像、alt、Amazonリンクをまとめて更新する。
5. 記事の `modified_at` と商品確認日を実際の更新日に合わせる。
6. 商品記事チェックリストを再実行する。
7. 旧商品→新商品の変更理由をレビュー記録に残す。

### 代替商品が適切でない場合

無理に商品リンクを維持せず、商品ブロックを削除または一般的な選び方の説明へ戻す。

## 7. 一時的な品切れの場合

- 数日程度の品切れだけで即時差し替えしない。
- メーカー公式で現行商品なら `TEMPORARILY_UNAVAILABLE` として再確認対象にする。
- 長期間継続、公式で旧製品化、後継品への移行が確認できた場合は `DISCONTINUED` または `REPLACED` とする。

具体的な日数を絶対基準にはしない。季節商品・災害需要による一時的な在庫変動も考慮する。

## 8. Creators API等を利用できる場合

公式APIが利用可能になったら、以下のみ自動化候補とする。

- ASINの有効性
- 商品名・主要情報の取得
- 提供される範囲での価格・在庫/購入可否情報
- 最終確認日時の記録
- `REVIEW_REQUIRED` 候補の抽出

自動判定だけで商品を差し替えたり削除したりしない。
**API検知 → REVIEW_REQUIRED → 仕様確認 → 記事修正**の順とする。

APIキー、シークレット、認証トークンはprivateリポジトリにも平文保存せず、GitHub Secrets等で管理する。

## 9. 実装時の推奨データ項目

将来、公開リポジトリに商品状態管理ファイルを作る場合は、秘密情報を含めず次のような項目だけを保持する。

- product_id
- asin
- product_name
- manufacturer
- source_page
- amazon_url
- manufacturer_url
- status
- last_checked_at
- checked_by (`manual` / `api`)
- replacement_product_id
- note

## 10. 禁止事項

- Amazon商品ページの定期スクレイピングをGitHub Actionsで行う
- 品切れ判定だけで自動的に別ASINへ差し替える
- 仕様を確認せず商品名・画像・価格だけ変更する
- 販売終了商品へのリンクを収益目的で放置する
- 実際に確認していない日付へ「確認日」を更新する
- API認証情報を公開ファイルへ保存する

## 11. 現在の運用

2026-09-07時点では、Creators API等の利用可否・認証情報が未確定のため、**手動確認を正規フォールバック運用**とする。

API利用可否が確認できたら、本ポリシーを変更せず、自動検知部分だけを追加する。
