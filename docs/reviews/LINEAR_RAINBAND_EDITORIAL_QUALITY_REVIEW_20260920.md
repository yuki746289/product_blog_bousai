## 1. 結論

前回の公開前レビューは不十分だった。

既存ルールにはすでに以下がある。

- 検索意図・読者の疑問に直接答える
- 結論、判断条件、理由、具体例を持つ
- 結論を最初の1〜2文で示す
- 各章を独立メモの寄せ集めにしない
- 機械的な定型文、抽象的な注意書き、章構造の使い回しを避ける
- 制作メモ的な「候補」「確認ポイント」「記事内容に沿って」等を公開本文へ出さない

## 2. B067で確認した主要問題

### 2.1 見出しが読者向けの答えではなく、編集メモ・論点メモに見える

例:

- 線状降水帯の主な事例とデータ
- この特集の構成
- 線状降水帯とは
- 古い豪雨も線状降水帯だったのか
- 線状降水帯は増えているのか
- どの地域で多いのか
- 「100年に一度」は出典が確認できたものだけ載せる
- この特集を防災行動につなげる

問題は疑問形そのものではない。疑問形を使う場合、見出し直後に答えを明示すべきだが、現状は「ここは誤解しやすい」「データを分ける必要がある」など編集上の説明から始まる章がある。

### 2.2 「線状降水帯は増えているのか」に答えが先にない

現状は、2023年以降の現行事例、制度変更、3種類のデータを説明した後に将来シミュレーションへ進むため、読者が「結局どうなのか」を自分で組み立てる必要がある。

章の冒頭で最低限、次を明示する。

> 現在の短い公式事例系列だけでは「近年、実際の発生回数が長期的に増えた」とは断定できない。一方、同じ条件で比較した気候シミュレーションでは、温暖化に伴って線状降水帯が増える方向が示されている。

この2文を先に置き、その後で「なぜ断定できないか」「将来予測は何を示すか」を説明する。

### 2.3 制作側の都合が本文に出ている

B070冒頭には、都道府県別ランキングを「CSVを統一ルールで集計した後に追加します」という公開後の制作予定が本文へ出ている。

これは読者向け情報ではなく、制作・運用メモなので公開本文から外す。

### 2.4 特集トップとして論点が多すぎる

B067は「定義・歴史・増加・地域・雨量・表現ルール・情報制度・警戒レベル・行動」を一枚に載せており、各章が短い概要になりやすい。

特集トップは次の3役に絞る案を優先する。

1. 線状降水帯とは何か
2. 読者がまず知るべき結論（どこで多い / 増えていると言えるか / 情報が出たらどうする）
3. 詳細記事への案内

詳細な制度史・年表・雨量記録は子記事へ任せる。

## 4. 「AIが書いたように見える」原因

文章を口語化することでは解決しない。主因は以下。

1. 各記事で「この記事では〜整理します」が繰り返される
2. 「一括りにしない」「〜だけで判断しない」「〜を分けて確認する」が地域記事で反復する
3. 事実 → 免責・注意 → 例外、の順が多く、記事固有の主張が弱い
4. 見出しが「執筆者が何を整理するか」を示し、「読者が何を知れるか・何が分かるか」を示していない
5. 正確性を優先するあまり、結論を弱める表現が多い
6. 兄弟記事で章構造が近く、地域名と事例だけを差し替えた印象が出る

## 5. チェックリスト運用の是正案

既存ルールは削除せず、次をハードゲートとして追加・運用する。

### HG-01 問い見出しの即答
疑問形H2/H3は、原則として直後1〜2文に暫定結論を置く。
「断定できない」が答えなら、そのこと自体を明示する。

### HG-02 公開見出しの編集メモ禁止
「この特集の構成」「どう記録するか」「確認ポイント」等、制作側の作業名に見える見出しは、ナビゲーション等の明確な用途がない限りFIX。

### HG-03 制作予定・内部TODO禁止
「後で追加する」「集計後に追加する」「今後調査する」等は公開本文へ置かず、backlogへ移す。

### HG-04 兄弟記事の構成重複
同一特集の3記事以上で同種のH2構成・注意書きが連続する場合は、記事固有の問い・事例・結論へ再設計する。

### HG-05 answer-first
title/H1が疑問・比較・判断を約束している場合、リードまたは最初の主要章で答えを明示する。
「説明を読めば分かる」状態はPASSにしない。

### HG-06 AI定型句レビュー
「この記事では〜整理します」「〜を一括りにしない」「〜だけで判断しない」が複数記事で機械的に反復していないか、特集単位で横断確認する。

## 6. サイト全体への波及確認

B001-B081を制作メタ表現・定型句の兆候で横断スキャンしたところ、線状降水帯特集以外にも「この記事では〜整理します」「〜で整理しています」等が多数存在する。

ただし、単語出現だけでは不具合判定できない。例えば「避難先の第二候補」は正常な読者向け表現であり、「候補」という語だけで削除対象にはしない。

よって、サイト全体は機械的置換せず、次の順で人間編集レビューを行う。

1. title/H1への答えが冒頭にあるか
2. 見出しが読者向けか、制作メモ化していないか
3. 章が独立メモの寄せ集めになっていないか
4. 同カテゴリ・兄弟記事で構成や定型句が使い回されていないか
5. 「結局何を言いたいか」が各主要章で1文に要約できるか

優先対象は、特集・カテゴリトップ・pillar記事、その後にdetail/practical記事とする。
