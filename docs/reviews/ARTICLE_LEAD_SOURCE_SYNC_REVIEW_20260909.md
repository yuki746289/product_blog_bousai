# B001–B060 公開概要・本文同期レビュー

Created: 2026-09-09 17:00 JST

## 背景

2026-09-09の冒頭概要レビューでは、主に `content/articles/*.md` の導入と本文構造を確認し、B001–B060を最終PASSとした。

その後、B056「鹿児島市・桜島の噴火史」の公開ページで、Markdown側には鹿児島市・桜島・大正噴火・降灰データを含む十分な導入がある一方、公開HTMLの `article-lead` には古い汎用的な1文が残っていることを確認した。

つまり、前回レビューの不足は「Markdownの要約品質」だけではなく、**レビュー済みMarkdownと公開概要が同期しているかを60記事すべてで強制確認していなかったこと**にある。

## 根本原因

Markdownからpreview HTMLへの同期処理は、本文全体を安全に再生成できる一部の記事のみを対象としていた。

そのため、専用レイアウト等を保持する記事では本文を意図的に再生成しない一方、`article-lead` も同期対象外となり、Markdownを改善しても公開概要だけ古い文が残る可能性があった。

B056はこのケースに該当した。

## 修正方針

本文全体の再生成可否と、概要の同期を分離する。

- 本文全体: 従来どおり安全に再生成できる記事だけ同期する
- `article-lead`: B001–B060の60記事すべてを同期対象にする
- 原則: Markdown導入を公開概要の編集正本とする
- 既存の手動レビューで補強したB013 / B021 / B024 / B029 / B057は、現時点では互換例外として維持し、本文由来の要約であることを回帰テストする

## 新しい品質原則

概要はタイトルを言い換えて作るのではなく、**完成した本文を圧縮して作る**。

1. タイトルで約束した内容を本文で回収する
2. 本文の主要章を2〜5個程度の意味のまとまりへ圧縮する
3. 圧縮結果を概要へする
4. `タイトル ↔ 本文 ↔ 概要` を照合する

記事固有の情報が抜け、同カテゴリの別記事へそのまま流用できる概要は `FIX` とする。

### B056の判定例

旧公開lead:

> 日常的な降灰への対応と大規模噴火への備えを分けて整理します。

これは鹿児島市・桜島の記事であること、大正噴火や降灰データを材料にすることが分からず、別の火山記事にも流用できるため不足。

Markdown導入には次の固有情報が含まれているため、公開leadはこの導入を反映する。

- 桜島
- 鹿児島市
- 1914年大正噴火
- 近年の降灰データ
- 気象庁の降灰量階級
- 鹿児島市の大規模噴火想定
- 家庭での火山灰対策

## 回帰テスト

`tests/test_article_intro_map_review.py` で次を強制する。

- B001–B060の60IDをすべて同期対象として持つ
- 互換例外5記事を除く55記事は `preview article-lead == Markdown intro`
- 互換例外5記事はレビュー済みleadが公開previewに存在する
- B056の公開leadに `桜島 / 鹿児島市 / 大正噴火 / 降灰` が含まれる
- B056はMarkdown導入と公開leadが一致する
