## B017 地震保険の基本

### 判定

`MINOR_REVISION`

### 良い点

- 火災保険と地震保険の役割を分けている。
- 建物・家財・自動車を別契約として説明している。
- 地震保険金額30〜50％、建物5,000万円・家財1,000万円の制度上の限度を、完全再建費ではなく生活再建資金として説明している。
- 全損・大半損・小半損・一部損の4区分を表で示している。
- 加入判断を「地域リスクだけ」ではなく、住宅ローン・仮住まい・家財買替・手元資金不足で考えている。
- 被災後の `安全 → 記録 → 連絡 → 案内確認` の順序がある。
- 証券確認チェックがあり、初心者でも確認対象が分かる。

### 軽微な改善点

後半の次の章は役割が近く、内容が一部重なる。

- `契約するかは地域リスクだけで決めない`
- `加入判断は「被災後の資金不足」で考える`
- `契約確認チェック`
- `証券を見るときは『建物』と『家財』を分けて確認する`

内容不足ではなく、**後から追加した説明が重なっている編集上の問題**である。

### 修正方針

- 加入判断は「被災後の資金不足」で1章に集約。
- 証券確認は「証券を開いたら5点」に集約。
- 数値・制度説明は現行維持。
- 新しい情報の追加より、重複整理を優先する。

## B009 冠水した道路を車で走る危険

### 判定

`PASS_NO_CHANGE`

### 理由

- 「安全な一律水深を作らない」という結論が明確。
- 前の車が通った、水深、SUV、低速走行等の典型的誤解を理由付きで否定している。
- 流れ、路面、短時間の水位変化、車種差という危険要因が具体的。
- `止まる → 入らない → 戻る/迂回 → 情報確認 → 運転自体を中止` の行動手順がある。
- アンダーパスを避ける代替ルート、引き返せる地点、夜間・強雨時の見えにくさまで生活場面へ落としている。
- すでに進入した場合も「必ずバック」等の危険な固定手順を作っていない。
- EV/HVも別の安全水深を作らず、浸水後の高電圧系統へ触れない境界がある。

トリアージで短いH2が多く出たのは、危険要因を参照しやすく分割しているため。統合・増量しない。

## B011 台風・洪水で水没した車は車両保険の対象になる？

### 判定

`PASS_NO_CHANGE`

### 理由

冒頭で次の4点を明示している。

1. 車両保険の有無
2. 台風・洪水・高潮が補償範囲か
3. 免責・自己負担・保険金額
4. 原因が地震・津波ではないか

被災後も、

`人の安全 → 始動しない → 保険/ロードサービスへ連絡 → 安全な範囲で記録`

の順が明確。

さらに、

- 駐車中と走行中の水没
- 地下駐車場
- レッカー・保管先
- 車内の持ち物
- 代車
- 証券が手元にない場合
- 事故受付番号

まで、実際の手続きで迷いやすい論点が具体的に説明されている。

短い章は重複ではなく、事故後の個別確認項目として機能しているため変更しない。

## B041 津波からどう避難する？

### 判定

`PASS_NO_CHANGE`

### 理由

高リスク記事のため、短いH2が多いこと自体を問題にしない。

現在の各章は、

- 強い揺れ・長い揺れなら警報を待たない
- 揺れがなくても警報が出れば避難
- 注意報と警報の対象差
- 海から離れるだけでなく高い場所へ
- 避難場所が津波対応か確認
- ハザード区域外を絶対安全としない
- 徒歩原則
- 車を全国一律禁止とも言わない
- 家族を迎えに危険区域へ戻らない
- 荷物を取りに戻らない
- 川沿いも対象
- 第一波が最大とは限らない

など、**一つずつが独立した安全判断**である。

特に「近所の学校＝津波避難先ではない」「指定緊急避難場所は災害種別で確認」という説明は、今回追加した初心者向けルールとも整合する。

章数を減らすために統合すると、緊急時の参照性を落とすため現状維持とする。

## B028 ポータブル電源は防災に必要？

### 判定

`NEEDS_REVISION`

### 良い点

- 商品名からではなく「何を何時間使うか」から始めている。
- WhとWを分けて説明している。
- `500Wh ÷ 50W = 10時間`をそのまま保証時間としない説明がある。
- 高出力家電より通信・照明・健康維持等を優先する考え方がある。
- 小型・中容量・1kWh級を用途、容量、定格出力、重量で比較している。
- 購入前のメーカー追跡性、リコール、保管温度、購入後の実機接続確認まで扱っている。
- 医療機器を一般家電と同じ判断で接続しない安全境界がある。

### 修正すべき点1：15個の連番H2が機械的

現在は `1.` から `15.` まで同じ階層で続き、次の異なる目的が同列に見える。

- 必要性を判断する
- 容量を決める
- 商品を比較する
- 安全に保管・点検する

内容自体は悪くないが、**読者の意思決定段階が見出し構造に反映されていない**。

### 修正すべき点2：「半年に1回」は記憶依存

`半年に1回は残量・動作・リコールを確認する` は、今回の新ルール「記憶に頼らない継続設計」に抵触する。

### 修正方針

H2を次の4ブロックへ整理し、その中をH3で分ける。

1. **自分の家庭に必要か判断する**
2. **容量・出力を決める**
3. **商品を比較する**
4. **購入後に安全に維持する**

定期点検は、

- 台風シーズン前
- 夏・冬の停電対策の切り替え時
- 防災用品の点検日
- スマートフォンのカレンダーによる繰り返し予定

など、既存の生活イベントと結び付ける。

「半年」という間隔を残す場合も、覚えておくのではなくカレンダー登録等まで本文へ書く。

## B047 真夏に停電したらどうする？

### 判定

`PASS_NO_CHANGE`

### 理由

冒頭で、

`室内の暑さ確認 → 水分 → 体を冷やす → 日射回避/涼しい場所 → 冷房のある移動先 → 症状時の救急対応`

という順序が明確。

加えて、

- 高齢者・乳幼児・持病のある人を早めに移動対象とする
- 扇風機だけで高温環境を安全と判断しない
- 暴風・冠水等で移動自体が危険な場合を考慮
- 車を冷房代わりにする場合の別リスク
- 発電機を屋内で使わない
- 自力で水を飲めない・意識がない場合の救急要請
- 夜間でも室内が暑い場合
- 停電＋断水
- すぐ外へ移動できない数時間への備え

まで具体化されている。

高リスク記事として必要な「何をする」「いつ移動する」「何が危険」「どの状態なら救急」のつながりが十分で、短いH2を理由に長文化しない。
