## 5. U10 Amazon品切れ・販売終了対策

### 5.1 現在の状態

状態: **FALLBACK_READY**

以下は2026-09-08までに実装済み。

- `docs/AMAZON_WORK_PREFLIGHT.md` を新設
- `docs/AFFILIATE_POLICY.md` をAmazon作業開始ゲート化
- `docs/AMAZON_PRODUCT_AVAILABILITY_POLICY.md` を正本から同期
- 記事別チェックリストへAmazonプレフライト証跡を追加
- Amazonルール参照契約をCIテスト化
- B060でASIN・画像・CTA・価格根拠のプレフライト証跡を記録

今後、Amazonリンク・ASIN・商品画像・価格・商品差し替えを扱う作業では、過去の会話や記憶だけで進めず、作業単位ごとにAmazon専用ルールを読み直す。

### 5.2 APIを利用できる場合

Amazon公式の現行商品API（Creators API等）がアカウント条件上利用可能な場合のみ、自動検知を追加する。

- 認証情報はGitHub Actions Secrets等の非公開領域でのみ管理する。
- 掲載ASINの提供状態等を取得し、問題候補を `REVIEW_REQUIRED` として抽出する。
- `OUTOFSTOCK` / `UNAVAILABLE` 等を検出しても無関係商品へ自動差し替えしない。
- 取得失敗を「在庫あり」とみなさない。

API自動化は現状の公開運用を止めるブロッカーではない。

### 5.3 APIを利用できない間

- 手動確認を正式なフォールバックとする。
- Amazon商品ページHTMLの定期スクレイピングによる在庫判定は行わない。
- 一時欠品と長期欠品・販売終了を区別する。
- 長期欠品・終売を確認した商品は、同用途の確認済み商品へレビュー後に差し替える。
- 適切な代替品が確定できない場合は、商品名・型番固定の検索リンク等へ安全に退避できる。
- 品切れ確認日、差し替え日、旧ASIN、新ASINまたは代替リンクを商品メモへ残す。

## 6. U11 Accaii一時利用

- 立ち上げ初期の補助解析として一時導入。
- 個別ページではなく共通解析partialから読み込む。
- `?ci_audit=1` では読み込まない。
- GA4 / Search Consoleで十分な実データが蓄積した後に削除する。
- 削除忘れ防止のため `WAITING_DATA` として残す。

## 7. U12 GitHub Actions節約モード

- 2026-09-05時点で月間利用枠が逼迫したため、自動実行を縮小済み。
- realtime JSONのActions定期更新は一時的に6時間間隔。
- Content freshness checkは対象PR・手動・週1回中心。
- Production Lighthouse auditは必要なUI・性能変更後の確認中心。
- 複数修正を作業ブランチへまとめ、mainへの反映回数を抑える。
- **2026-10-01以降**に利用状況を再評価する。

## 8. 現在の優先度

1. 通常のサイト改善・記事企画は継続する。
2. U04〜U07はデータ蓄積待ちのため、現時点で無理に実施しない。
3. U10は手動フォールバックが成立しているため、API自動化は利用条件が整った場合に実施する。
4. U11はデータ蓄積後にAccaiiを削除する。
5. U12は2026-10-01以降に再評価する。
6. U08は任意。必要な記事企画だけで利用する。

## 9. フィードバック後の扱い

ユーザー確認で問題が見つかった場合は、ChatGPT側で以下を行う。

- 原因切り分け
- リポジトリ修正
- 必要なら共通ルール・チェックリスト更新
- 自動テスト化可能な問題は回帰テスト追加
- 本番反映・スモーク確認

単発修正だけで終わらせず、再発防止まで検討する。
