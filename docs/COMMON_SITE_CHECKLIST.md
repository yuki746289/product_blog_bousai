# 全サイト共通 作成・レビュー・チェックリスト

更新日: 2026-09-23

このチェックリストは `COMMON_SITE_REVIEW_FRAMEWORK.md` のP01〜P22を、実制作・レビューで確認しやすい形へ落とした共通版である。

サイトごとにすべてを必須にせず、サイト個別プロファイルで `REQUIRED / CONDITIONAL / N/A` を確定してから使用する。`N/A` は理由を残す。

判定値: `PASS / FAIL / TODO / N/A`

共通チェックIDは防災記事チェック等と衝突しないよう **`GC01〜GC21`** を使用する。

## GC01 ページ目的・内容品質（P01）

- [ ] 読者の主要な疑問へ直接答えている
- [ ] ページの役割を1文で説明できる
- [ ] 説明不足・水増し・章内重複がない
- [ ] 同じテンプレートや章構成の使い回しが過剰でない
- [ ] 結論、条件、例外、次の行動が整理されている
- [ ] 既存ページで十分な内容を新規ページとして重複作成していない

## GC02 正確性・安全性・根拠（P02/P03）

- [ ] 分野固有の安全・業務ルールを確認した
- [ ] 重要主張は一次情報・公的情報・原典を優先した
- [ ] 事実、推測、編集上の提案を混同していない
- [ ] 数値には期間・単位・条件・出典がある
- [ ] 情報確認日・更新責任・再確認時期を必要に応じて管理した
- [ ] 誤解により人命・健康・金銭・権利へ重大な損害が出る表現を安全側でレビューした

## GC03 検索・SEO（P04）

- [ ] 主検索意図とページ内容が一致している
- [ ] title / H1 / meta descriptionがページ固有である
- [ ] キーワードの不自然な羅列がない
- [ ] 既存ページとのカニバリを確認した
- [ ] canonical / noindex / sitemap等がページ役割と一致する
- [ ] 構造化データを使う場合、実際の表示内容と一致する

## GC04 情報設計・内部導線（P05）

- [ ] カテゴリ、URL、パンくず、title、H1の役割が整合する
- [ ] 新規ページを孤立させていない
- [ ] 親ページ→詳細ページ、詳細ページ→親・関連記事の導線がある
- [ ] リンク文言だけで行き先が分かる
- [ ] 「こちら」「詳しく」だけの曖昧リンクを避けた
- [ ] 情報記事・商品記事・Q&A等のページ種別を誤認させない

## GC05 UX / UI・デザイン（P06）

- [ ] PC / スマートフォン双方で主要情報を読みやすい
- [ ] 見出し、余白、強調、画像の情報階層が適切
- [ ] 強い背景色・装飾・影を使いすぎていない
- [ ] 重要情報が視覚的に埋もれていない
- [ ] CTAが本文理解を邪魔しない
- [ ] 新規ページだけがサイト全体のデザインから不自然に浮かない
- [ ] 太字・背景色等はセル/段落全体へ機械的に適用せず、意味のある語句・数値を選択的に強調する

## GC06 アクセシビリティ（P07）

- [ ] 見出し階層が意味的に正しい
- [ ] キーボードで主要操作が可能
- [ ] フォーカスが視認できる
- [ ] 画像altが内容と役割に合う
- [ ] 色だけで状態・重要度を伝えていない
- [ ] タップ対象・文字サイズが実用的
- [ ] 表や横スクロール領域を操作・理解できる
- [ ] 動きを使う場合 reduced-motion 等を考慮した

## GC07 読者・状況設計（P08）

- [ ] target_readerを説明できる
- [ ] usage_contextを説明できる
- [ ] knowledge_levelを考慮した
- [ ] reader_problem / reader_goalが明確
- [ ] ペルソナを使う場合、内容や導線を変える根拠のある属性だけを採用した
- [ ] 根拠のない架空プロフィールを作ること自体を目的にしていない

## GC08 マーケティング・ジャーニー・CRO（P09）

- [ ] entry_path / page_job / next_actionが自然につながる
- [ ] conversion_pathが読者利益と矛盾しない
- [ ] CTAの順序・強さが適切
- [ ] 不安・焦り・誤認を利用してCVを上げようとしていない
- [ ] 関連ページ・商品・問い合わせ等への遷移理由が本文文脈にある

## GC09 ブランド・コンテンツデザイン（P10）

- [ ] tone of voiceがサイト内で一貫する
- [ ] 用語表記が統一されている
- [ ] 制作側の内部用語を読者本文へ出していない
- [ ] 公的情報・事実と、自サイトの解説・意見を区別できる
- [ ] 「おすすめ」「安全」「安心」「必ず」等の強い表現に根拠がある

## GC10 商品・EC・アフィリエイト（P11、条件付き）

- [ ] 商品選定理由がページ内容と一致する
- [ ] 商品説明と本文が分離せず、自然な文脈で紹介される
- [ ] 比較軸が購入判断に有用
- [ ] 商品名・画像・容量・型番・数量が一致する
- [ ] 価格は確認日・変動可能性を明示し、変動値を固定保証しない
- [ ] 広告・アフィリエイト表示が適切
- [ ] 商品を公的推奨・安全保証のように見せない
- [ ] 欠品・終売時の運用を考慮した

## GC11 計測・分析・グロース（P12、条件付き）

- [ ] KPIがページ目的と整合する
- [ ] GA / Search Console等の計測に不要なデータを送らない
- [ ] 自動テスト・監視アクセスを実ユーザー分析へ混入させない
- [ ] A/Bテスト等は安全性・アクセシビリティを悪化させない
- [ ] 相関を因果として断定しない
- [ ] 十分なデータがない場合は「データ不足」と扱う

## GC12 Web技術・信頼性（P13）

- [ ] HTML / CSS / JavaScriptの構文・主要機能を確認した
- [ ] レスポンシブ表示を確認した
- [ ] 内部リンク・画像・主要アセットの欠落がない
- [ ] 外部API・外部画像の失敗時挙動を確認した
- [ ] 「取得失敗」と「情報なし」を混同しない
- [ ] 変更範囲に応じたビルド・テスト・スモークを実施した
- [ ] パフォーマンスを大きく悪化させる変更がない

## GC13 セキュリティ・プライバシー（P14）

- [ ] secret・APIキー・パスワードをリポジトリ・公開HTMLへ含めない
- [ ] 外部JavaScript・計測・APIを必要以上に増やしていない
- [ ] 個人情報・URLパラメータ等の送信範囲を確認した
- [ ] フォーム・認証・権限がある場合は入力・認可をレビューした
- [ ] ログやエラー出力に機密情報を残さない

## GC14 法務・権利・広告表示（P15）

- [ ] 画像・図表・引用の権利条件を確認した
- [ ] 必要な作者・ライセンス・出典情報を保持した
- [ ] 商標・商品名を誤認させる使い方をしていない
- [ ] 広告・アフィリエイトを編集記事と誤認させない
- [ ] プライバシーポリシー等へ新規計測・外部サービスを反映した
- [ ] 法的判断を根拠なく断定していない

## GC15 ローカライゼーション（P16）

- [ ] 対象国・地域の制度・生活文脈と整合する
- [ ] 海外制度・海外製品仕様を対象地域の一般基準として扱っていない
- [ ] 単位、日付、通貨、数量表現が対象読者に自然
- [ ] 画像の文化・地域文脈が内容と合う
- [ ] 地域差を全国・全世界一律に断定していない

## GC16 コミュニティ / UGC（P17、条件付き）

- [ ] 投稿・コメント・レビューのルールがある
- [ ] 通報・削除・モデレーション運用がある
- [ ] 個人情報・著作権・誤情報・スパムを考慮した
- [ ] UGCと運営者本文を明確に区別する

## GC17 運用・ガバナンス（P18）

- [ ] 正本が明確
- [ ] 複数リポジトリ・複数生成物の同期範囲が明確
- [ ] published / modified / source checked / reviewed 等の日付意味を混同しない
- [ ] 定期レビュー対象・期限を管理する
- [ ] 同じ問題が再発した場合、ルール・テストへの昇格を検討する
- [ ] 一時修正だけで正本と本番を乖離させない
- [ ] 新機能追加時にN/A項目を再評価する

## GC18 配信・SNS・PR（P19、条件付き）

- [ ] OGP・シェア時のタイトル・画像が内容と一致する
- [ ] SNS文脈で誤解を生む切り取りになっていない
- [ ] 検索以外の流入施策がサイトのブランド・安全基準と矛盾しない

## GC19 事業・収益モデル（P20、条件付き）

- [ ] 収益モデルが読者価値と矛盾しない
- [ ] 収益導線のために安全性・正確性・アクセシビリティを弱めていない
- [ ] 広告・アフィリエイトの依存度と運用負荷を把握している
- [ ] 継続的に保守できる仕組みになっている

## GC20 データ・統計・可視化（P21、条件付き）

- [ ] 分母、母集団、期間、単位、欠損処理が明確
- [ ] 推計・実測・公称値を区別する
- [ ] ランキング・平均・割合を誤解させない
- [ ] グラフ軸・尺度で視覚的に誇張しない
- [ ] 不確実性・限界を必要に応じて表示する

## GC21 サポート・サービス運用（P22、条件付き）

- [ ] 問い合わせ・ヘルプ・FAQへの導線が分かる
- [ ] 障害時や手続き変更時の案内責任が明確
- [ ] 予約・解約・返品・購入後支援等がある場合、利用者手続きを確認した
- [ ] サポート負荷を運用可能な範囲にしている

## 最終横断判定

- [ ] 適用すべきP01〜P22に未判定がない
- [ ] `N/A` に理由がある
- [ ] REQUIRED項目にFAIL/TODOが残る場合、公開可否を明示した
- [ ] 安全・法令・権利・正確性をSEOや収益より優先した
- [ ] 同じ問題を個別修正だけで終わらせず、共通ルール化の要否を検討した
