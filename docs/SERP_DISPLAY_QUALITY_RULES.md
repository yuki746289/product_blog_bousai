# 防災ブログ SERP表示品質ルール

作成日: 2026-09-11
適用先: 防災くらしガイドの記事作成・競合調査・SEOレビュー

## 1. 目的

Google検索結果では、ページの `<title>` や `meta description` がそのまま表示されるとは限らない。
Googleは検索クエリやページ内容等に応じてタイトルリンクやスニペットを自動生成するため、記事品質はページ内だけでなく、**検索結果上で「何の記事か」「検索者の疑問に答えそうか」が伝わるか**も確認する。

本ルールは、検索結果だけを最適化するための文章制作を目的としない。
読者にとって自然で正確な本文を前提とし、重要な回答部分が検索結果に抜粋されても意味が通る文章構造を作る。

## 2. 基本原則

- `<title>` は検索意図が一目で分かる、ページ固有の簡潔な表現にする。
- H1はtitleと意味をそろえ、Googleが別タイトルを生成してもページ主題がぶれない構造にする。
- `meta description` はページ固有の内容を正確に要約する。ただし、常にそのまま表示される前提では設計しない。
- Googleは本文からスニペットを生成する場合があるため、主要な回答段落は単独で読んでも意味が通るようにする。
- 検索クエリごとに異なるスニペットが表示される可能性を前提とする。
- SERP表示の改善を理由に、危険な断定、誇張、煽り、キーワード詰め込みを行わない。
- Search Consoleのデータが少ない記事、または既に5〜10位前後で露出している記事では、観察結果だけでtitleを頻繁に変更しない。

## 3. 記事作成ルール

### 3.1 title

- 主検索意図を1つ決め、その意図が自然に伝わる。
- 記事の実内容と一致する。
- 同一サイト内の別記事と役割を区別できる。
- 長すぎる説明や同義語の羅列を避ける。
- 不要な年号、地域名、煽り文句を付けない。
- H1、主要見出し、本文の主題と矛盾しない。

### 3.2 meta description

- 記事で分かることを具体的に要約する。
- 本文にない結論、保証、数値、商品評価を書かない。
- 単なるキーワード一覧にしない。
- 検索者が「この記事で何が判断できるか」が分かる内容を優先する。
- Googleが本文をスニペットに採用しても問題ない本文品質を別途確保する。

### 3.3 本文・見出し直下の回答

主要なH2/H3では、必要に応じて見出し直下の1〜2文で、その見出しに対する結論または要点を示す。

良い状態:

- 見出しと直後の文章だけでも論点が分かる。
- 検索結果に1〜2文だけ抜粋されても意味が通る。
- 主語・対象・条件が文章内に含まれている。
- 「何をするか」「何に注意するか」が明確である。

避ける状態:

- 「この場合は注意が必要です」のように、前後文脈がないと意味が分からない。
- 「前述の通り」「上記の理由で」だけで結論を述べる。
- 見出し直後が長い前置きで、回答が数段落後に出てくる。
- SERP表示を狙うために同じキーワードを不自然に繰り返す。

### 3.4 単独抜粋耐性

重要段落は、文章全体の自然さを損なわない範囲で次を満たす。

- 対象が分かる。
- 条件が分かる。
- 行動または結論が分かる。
- 安全上必要な但し書きが欠落しない。
- 「これ」「それ」「その場合」だけに依存しない。

ただし、すべての段落を検索スニペット向けの定型文にしない。記事全体の読みやすさを優先する。

### 3.5 検索結果用パンくず

- BreadcrumbListは内部URLをそのまま読ませるためではなく、検索者がページ位置を理解するための情報階層として設計する。
- 基本形は **「防災くらしガイド › ユーザー向けカテゴリ/特集 › 短いページ名」** とする。
- title全文を末尾へ機械的に複製しない。
- 固定3階層にせず、特集トップ等は2階層などページ役割に応じた自然な深さとする。
- 線状降水帯県別は原則「防災くらしガイド › 線状降水帯 › ○○県」。
- 記事役割が異なるページは、URL格納場所ではなく実内容に合わせる。例: 大阪府の大雨・都市型水害は「防災くらしガイド › 地域別 › 大阪府の大雨・都市型水害」。
- Googleが指定どおりのパンくず表示を保証するものではないため、構造化データはサイト側の意図を正確に示す目的で運用する。

## 4. 競合・SERP調査ルール

主要クエリごとに、可能な範囲で以下を記録する。

- 調査日
- 検索クエリ
- 順位
- サイト / URL
- Google検索結果に実際に表示されたタイトル
- ページ側の `<title>` / H1との相違
- Googleによるタイトル書き換えの有無または可能性
- 実際に表示されたスニペット本文
- スニペットが本文のどの箇所から取得されたか（特定できる場合）
- meta descriptionとの一致 / 不一致 / 一部一致
- 検索意図への回答度
- SERPだけを見たときの内容理解のしやすさ
- クリック理由が明確か
- 自サイトとの差

検索結果はユーザー、地域、端末、時期等によって変化し得るため、1回の目視結果を固定的な事実として一般化しない。

## 5. SERP表示品質の判定

記事レビューでは以下を使用する。

### PASS

- titleから主検索意図が分かる。
- 実際の検索結果タイトルが記事内容と大きくずれていない。
- スニペットが本文またはmeta descriptionから生成されても意味が通る。
- 主要な回答段落が単独抜粋に耐えられる。

### FIX

- Google表示タイトルが記事内容を誤解させる原因がページ側にある。
- title / H1 /主要見出しの主題がずれている。
- スニペット候補になる重要段落が前後文脈に依存しすぎている。
- 検索意図への直接回答が見出しから遠すぎる。
- meta descriptionが本文内容と一致していない。

### MONITOR

- Search Consoleデータが少なく、変更効果を判断できない。
- 5〜10位前後で既に露出しており、title変更のリスクがある。
- SERP表示に課題はあるが、Google側の変動かページ側の問題か切り分けできない。

### N/A

- noindexページ、検索流入を目的としない管理ページ等。

## 6. 既存記事の見直し方針

既存記事は一括改稿しない。

優先順位:

1. Search Consoleで表示実績がある記事
2. 平均順位5〜15位程度で改善余地がある記事
3. 表示回数が多いのにCTRが低い記事
4. Google表示タイトルがページ主題とずれている記事
5. スニペットが検索意図に対して弱い記事

順位が既に良い記事は、まずSERP表示と本文構造をレビューし、必要なら**局所修正**を行う。
title、H1、URL、記事全体構成の変更は、Search Consoleと競合調査を確認してから判断する。

## 7. 競合調査との連携

競合調査では「記事本文が強いか」だけでなく、**Googleがそのページのどの情報を検索結果で代表させているか**を確認する。

比較観点:

1. 上位サイト vs 自サイト
2. 上位サイト vs ニッチサイト
3. ニッチサイト vs 自サイト
4. SERP表示品質（タイトル・スニペット）

コンテンツギャップがなくても、SERP上で検索意図への回答が競合より分かりにくい場合は改善候補とする。

## 8. 禁止事項

- スニペット表示を保証する表現をルール化しない。
- meta descriptionが必ず表示される前提で評価しない。
- 1回の検索結果だけでtitleを変更しない。
- 順位が上がるという理由だけで不自然なキーワードを追加しない。
- 競合のタイトル・スニペットをコピーしない。
- 検索結果向け文章のために本文の自然さ、安全性、正確性を下げない。
