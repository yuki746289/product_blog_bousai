## 1. 目的

全記事を「事実が正しい」「総文字数が足りる」だけで公開可としない。

最終レビューでは、読者が記事を読んだ結果として、

- 自分に関係する条件が分かる
- なぜ必要か理解できる
- 初めてでも確認・操作・行動まで進める
- 現実の生活で取り得る行動になっている
- 必要な関連記事・商品記事へ自然に進める
- 図や画像が必要な箇所では視覚的に理解できる
- 制作側のメモや未完成表現が一切見えない

状態を目標とする。

判定は `PASS / FIX / HOLD / N/A`。公開NG項目が1つでもあれば `PASS` にしない。

---

## 2. P0 公開本文の衛生チェック（最優先）

### 2.1 内部メモ・制作コメントを本文へ出さない

次のような制作側の都合・未完成表現は**公開本文では厳禁**。

- 「別途検討します」
- 「今後追加します」
- 「商品記事を作成予定です」
- 「この記事からAmazonへ直接つなげず…」
- 「商品候補」「採用理由」「記事内容に沿って選定」
- 「編集メモ」「作業メモ」「TODO」「FIXME」
- 「この箇所は後で修正」等の制作工程の説明

必要な内容が未作成なら、本文に制作事情を書かない。読者に現在提供できる情報だけで文章を完結させる。

### 2.2 読者向け文章への変換

不適切:
> 止水板の商品記事は別途検討します。

適切な方向:
> 止水板は開口幅、設置高さ、固定方法が製品ごとに異なるため、購入前に自宅の設置場所を測り、製品の適合条件を確認します。

### 2.3 公開前の強制確認

- [ ] Markdown本文に内部メモがない
- [ ] preview / production HTMLに内部メモがない
- [ ] 「予定」「検討」「候補」等が読者向け意味ではなく制作都合として残っていない
- [ ] 仮リンク、`href="#"`、準備中UIが残っていない
- [ ] 文章途中・仮見出し・重複章がない

**P0にFAILがあれば即修正。その他の品質判定へ進まない。**

## 3. 検索意図・自分ごと化

- [ ] 誰が何を知りたい記事か1文で説明できる
- [ ] 読者が「自分はどれに当てはまるか」を判断できる
- [ ] 地域・住宅・家族・時間帯・災害種別など、行動が変わる条件を必要な範囲で示す
- [ ] 例として「沿岸部→高潮・津波」「崖・山際→土砂災害」「川沿い・低地→洪水・内水」など入口を示す
- [ ] 生活環境だけで安全・危険を断定せず、最終確認先を公式情報へ接続する

## 4. 章ごとの説明充足

章の文字数は**ノルマではなく警告値**として使う。

| セクション | 警告目安 |
|---|---:|
| 導入・結論 | 200〜400字程度 |
| 通常H2 | 400〜800字程度 |
| 安全・避難・制度判断の重要H2 | 600〜1,000字程度 |
| H3 | 200〜500字程度 |

短くても目的を完結できればPASS。長くても説明が曖昧ならFIX。

主要章では必要に応じて次を確認する。

1. 結論 — 何をするか
2. 理由 — なぜするか
3. 方法 — 具体的にどうするか
4. 具体例 — 生活場面へ置き換えられるか
5. 条件・例外 — 一律でない点
6. 次の行動 — 何を見る、どこで確認するか

- [ ] 「確認する」「固定する」「安全に」「適切に」で説明を終えていない
- [ ] 行動と理由の因果がつながっている
- [ ] 初出語を突然出していない
- [ ] 独自の分類・段階・優先順位を使う場合、なぜその分け方が役立つか説明している

## 5. 初心者が操作完了できるか

「見てください」「確認してください」だけでは不足。

必要な記事では、どのサイト・ページを開くか、どこを操作するか、何を見るか、結果をどう判断へ使うかまで説明する。

例: ハザードマップなら「ポータルを開く→住所検索→災害種別→凡例・想定浸水深→自治体版確認」までを一つの作業として扱う。

- [ ] 「多めに」「十分に」だけで終わらず、算定方法や基準元を示す

- [ ] 実験値・自治体例・メーカー値を全国共通の安全保証に読み替えない

## 8. 画像・図解の挿入判断

### 8.1 画像を入れる価値が高い箇所

- 位置関係・配置・設置方法を説明する
- 3段階以上の手順を説明する
- A/Bの違いや分類を理解させる
- 「どこを見るか」を説明する
- 水・風・避難経路等の流れを理解させる
- 家の中・ベランダ・車内など空間配置を説明する
- 文章だけだと誤解しやすい因果関係がある

例: ハザードマップの見方、土のうの並べ方、ベランダ排水、家財の高所移動、停電の役割分担、津波避難の高低差。

### 8.2 画像の優先順位

1. 公式図・一次資料 — 安全判断、制度、警報体系、地図UIなど
2. 実物写真 — 商品、設備、実在場所、具体物
3. 独自図解 / AI生成図 — 空間配置、手順、比較、概念説明
4. 雰囲気写真 — 読解価値がある場合のみ

### 8.3 AI画像を使ってよいケース

一般住宅の模式図、家具・備蓄配置、土のう等の概念図、避難判断フロー、停電準備の分類図、特定の実在被害を再現しない一般防災イラスト。

### 8.4 AI画像を使わないケース

実在商品の商品写真代用、歴史災害の当時写真代用、現在の被災地・事故現場写真代用、公式UI再現、安全基準を根拠なく断定する図。

現実写真と誤認され得る場合は「図解」「イメージ」等のキャプションで区別する。

### 8.5 画像品質

- [ ] 章の理解を助ける目的が明確
- [ ] 枚数合わせではない
- [ ] 日本の住宅・生活環境と矛盾しない
- [ ] 図内文字は日本語で読みやすい
- [ ] スマホで潰れない
- [ ] altは画像の役割を説明する
- [ ] 同じ画像を複数記事へ機械的に使い回していない

## 9. 内部リンク・商品導線

- [ ] 詳細説明済みの関連記事がある場合、必要な文脈でリンクする
- [ ] 本文説明をリンクだけで省略しない
- [ ] 商品語が自然に出る場合、対応商品記事の有無を確認する
- [ ] 商品記事が存在する場合は原則 `情報記事 → 商品記事 → Amazon`
- [ ] 商品記事が未作成の場合、「今後作る」「別途検討」等を公開本文へ書かない
- [ ] Amazon関連作業では `AMAZON_WORK_PREFLIGHT.md` を必ず実行する

## 10. 安全・根拠・信頼

- [ ] 高リスク主張は一次・公的情報を優先
- [ ] 数値・制度・警報体系は現行情報か確認
- [ ] 公式情報とサイト独自説明を混同していない
- [ ] 一律の安全保証を作っていない
- [ ] 危険作業を免責だけで勧めていない
- [ ] AI生成画像・図を事実写真・公式図として見せていない
- [ ] 実体験、資格、被災経験を創作していない

## 11. AI定型感・編集品質

- [ ] 同じH2構造を複数記事で機械的に反復していない
- [ ] 「重要です」「確認します」「必要です」が連続していない
- [ ] 「場合があります」の連発で結論が消えていない
- [ ] 箇条書きが単なる名詞列ではなく、必要な理由・使い方がある
- [ ] 読者の実際の疑問順に記事が進む
- [ ] 制度説明を生活場面へ翻訳している
- [ ] 不自然な免責・注意書きを主文章より先に出していない

目的はAI判定回避ではなく、人間編集者が読んでも自然で具体的な完成記事にすること。
