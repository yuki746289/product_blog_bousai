## このpublicリポジトリ内のルール

`docs/` にあるルール・チェックリストは、記事制作、実装、レビュー、ローカルテストで使用する一時作業コピーとする。正本ではない。

既存のレビュー記録、テスト、作業手順から参照されているため、移行時点では削除しない。

## 作業手順

1. 作業開始時にprivate側の正本とpublic側の一時コピーを確認する。
2. 差分がある場合、private側を基準にする。ただしpublic側の変更を無条件に破棄せず、改善内容を確認する。
3. 作業中にルールを変更した場合、private側の正本へ反映する。
4. public側へ必要なルールを持ち込む場合、公開されても問題ない内容だけに限定する。
5. 作業完了時に正本と一時コピーの差分、記事・HTML・テストへの反映を確認する。

## 障害時の仕様不変ルール

タイムアウト、API失敗、ツール制約、接続切断、転送失敗が起きても、**ユーザー承認済みの仕様は変更しない**。

- 処理単位の縮小、再試行、再開位置の固定など、実行方法だけを変更する
- 成果物の種類・形式・表示方式・配置・動作・公開範囲を変更する場合は、実装前にユーザーへ差分を提示して承認を得る
- 「画像」をHTML/CSS図解へ置換するなど、異なる成果物を同等扱いしない
- 元仕様を実現できない場合は、勝手に代替せず未完了として報告する
- タイムアウト後は、最後に承認された仕様・完了条件・未完了タスクを確認してから再開する
- 内部テストがPASSしても、要求された成果物が公開画面・ファイル・機能として実際に確認できない場合は完了扱いにしない
- ユーザー承認前は最終状態を「確認待ち」とする

## 作業進捗の正本

サイト全体の作業進捗は `docs/WORK_PROGRESS.md` を正本とする。

- 作業開始前に対象タスクの `approved_spec`、`completion_criteria`、`next_action` を確認する
- 状態は `TODO / IN_PROGRESS / BLOCKED / INTERNAL_CHECK_DONE / USER_CONFIRMATION_PENDING / DONE / REOPENED` を使用する
- 内部チェック終了後もユーザー承認前は `USER_CONFIRMATION_PENDING`
- ユーザー承認後のみ `DONE`
- 完了後に不具合・仕様不一致が見つかった場合は `REOPENED`
- タイムアウト・接続切断後は `docs/WORK_PROGRESS.md` を再開地点とし、`next_action` から続ける
- 個別バックログ・記事別チェック・PR等は詳細記録として保持し、全体状態はこの台帳へ集約する

## Actions方針

- ルール同期専用のGitHub Actionsは作成・実行しない。
- private側のActions時間をルール同期に使用しない。
- ChatGPTのGitHub接続または通常のGit更新で、必要な作業時だけ同期する。
- public側では既存のテスト・本番デプロイ等、実装変更に必要なworkflowだけを使用する。

## 公開禁止情報

次はpublic側の一時コピーへ含めない。

- secret値、APIキー、パスワード
- FTP等の認証情報
- 非公開アカウント情報
- privateリポジトリ専用URLや内部管理情報
- 公開を意図しない事業・収益・運用情報

public側で一度コミットした内容は、後から削除してもGit履歴に残る前提で判断する。

## 対象外

個別記事本文、HTML/CSS/JavaScript、記事別レビュー記録、調査・出典・画像メモ、サイト固有コードは引き続きこのリポジトリで管理する。
